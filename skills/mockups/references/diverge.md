# Diverge

Offer alternatives when a consequential structural choice is unresolved. For a small change with an established pattern, or when the user asks for one recommendation, state the assumption and build directly.

## Compare useful alternatives

Pick the decision the brief makes consequential: page versus panel, inline versus modal, upfront versus progressive disclosure, user-driven versus automatic, or list versus canvas. Offer two or three materially different approaches when they clarify that decision. Do not invent probability or typicality scores, or add an unconventional option solely for novelty.

For each approach, briefly describe the places, user actions, flow, scenarios handled, tradeoffs and fit with the project's patterns. Judge visible status, user control, error prevention, recognition and consistency. Recommend one with reasons tied to the brief. Ask for a choice only when the unresolved decision would materially change the structure; respect a choice already made.

## Greenfield identity

When no design system exists, derive palette, type, density and shape from audience, domain and brand facts. Compare identity directions only when that choice is consequential or requested. Avoid defaulting to a favorite palette, and avoid forcing novelty when familiar conventions serve the user. Record the selected direction and its rationale in the handoff.

## Low-fi visuals

If spatial comparison would help, write `options.html` with labeled layouts and real copy, using grayscale and system fonts. For differences in logic or sequence, concise descriptions may suffice. Do not create an extra artifact solely to satisfy a fixed process.
