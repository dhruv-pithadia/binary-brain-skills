# Media guidance

Most working app screens need no generated artwork. Prefer existing assets, real product previews and code-native diagrams when they explain the task better. Keep interface text live and selectable rather than baked into an image. Never fabricate a functioning product feature in a preview.

When a bitmap would materially help, use the host's image-generation skill and available tool. Match the subject, composition, palette and empty text area to the actual layout. Keep the image local to the project with appropriate responsive dimensions, loading behavior and alternative text. Preserve transparency when the asset needs it. Follow the host's authorization rules; do not require redundant approval when the user already authorized generation, and do not connect a separate paid service without authorization.

If a useful image cannot be produced, choose a complete layout that works without it or report the missing asset. Do not ship an empty decorative placeholder as a finished design.

For requested before-and-after video or motion deliverables, use the installed video workflow, beginning with `hyperframes` when available. Do not bundle or invoke a separate Playwright/ffmpeg story renderer, watermark, snapshot scraper, or server as part of this skill. Respect the host's visual presentation and recording rules.
