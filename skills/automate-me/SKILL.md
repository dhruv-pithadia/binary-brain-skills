# Automate me

Read [host execution](references/runtime.md). Produce a concise personal mode that captures the user's actual conventions.

## Establish evidence and destination

Find an existing matching mode through the host catalog or the selected skills repository. Preserve its destination and invocation policy unless the user changes them. A request to update an existing mode is sufficient authorization for in-scope edits.

Use explicit instructions and current context first. Mine recent history only when available and relevant, scoped to the named project and time window. In T3 search/read project threads; never scan other projects or assume Cursor transcript folders. Report limited history instead of inventing preferences.

Separate an explicit preference from an inferred pattern. One clear instruction is authoritative within its scope; inferred preferences need recurring supporting evidence and a contradiction check. Do not elevate task-specific compromises into permanent habits.

For a large authorized corpus, bounded independent slices may help; otherwise work directly. Ask only the few questions that materially change the mode and cannot be answered from evidence. Avoid a mandatory interview sequence.

## Author

Use the available `skill-creator` workflow. Capture only non-default conventions that change decisions: communication, autonomy boundaries, verification, Git workflow, delegation, or durable constraints. Do not copy generic agent instructions or another person's style.

Use the user's chosen name or a neutral repository-specific name. Link genuinely required companion workflows rather than inlining them. Each rule should have a recognizable trigger, useful action, and scope. Keep the mode small and preserve supported existing sections.

Follow the host's supported metadata. Preserve existing explicit-only invocation; new skills use the host default unless the user requests otherwise. Format prose directly using plain-language guidance, not the UI-only `unslop` skill.

## Verify and deliver

Check that rules are supported, noncontradictory, and do not grant new publication/deployment permissions. Validate frontmatter, links, and invocation metadata. Show the result and evidence limits.

Save, commit, push, or install only within the user's actual grant and repository process. Do not create a worktree solely for standalone prose unless repository policy requires one. Do not claim automatic persistent learning without a saved discoverable artifact.
