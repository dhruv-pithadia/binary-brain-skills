# Unit template: every unit follows this exact rhythm

The repetition is deliberate: students learn where to look, which lowers cognitive load.

```
[Unit opener]  big number · unit title · course outcomes covered · tier tag
[One-line idea] the whole unit in one sentence (orange box)
[Concept sections] h2 per concept: plain explanation → diagram/table → example
[Key numbers]   blue box: the 4–8 figures worth quoting
[Cases]         2–4 cards: company/event, what happened, the number, the lesson
[Mnemonic]      purple box: letters assembled into a memorable phrase
[Exam trap]     red box: the classic confusion (e.g. "radical ≠ disruptive")
[Added from slides] teal box: content missing from the user's draft
[Exam practice] 1–3 Q&A blocks with marks + CO tags and full model answers
[60-second recall] dashed checklist of 5–8 self-test prompts
```

## Rules per element

**Tier tag.** `TIER 1 · HIGH WEIGHT` (red) for units that are heavily examined (from past papers, the syllabus weighting or the lecturer's emphasis); `TIER 2 · CORE` (teal) otherwise. If unknown, infer from the number of lecture hours and past-paper frequency, and say so.

**One-line idea.** At most ~35 words. It must name the unit's central mechanism, not just its topic. Bad: "This unit is about payments." Good: "Card payments run on a 4-party network that takes ~2.6% of every sale; FinTechs attack it by removing layers or turning acquiring into software."

**Concepts.**
- Lead with a 1–2 sentence definition in bold.
- Every framework becomes a visual (see `visuals.md`), never a paragraph alone.
- Comparisons (X vs Y) become 2–3 column tables.
- Processes become flows (CSS flow or Graphviz).
- Calculations get a formula box with the worked numbers, then a one-line interpretation.

**Key numbers.** Only numbers from the sources or verified research. Include the unit (%, $, ₹, bps, year).

**Cases.** Card format: name (year, founder if given) → the problem → what they did → 1–3 numbers → the lesson (link it to a framework).

**Mnemonic.** Prefer first-letter acronyms of the course's own lists (e.g. I-T-L-R-T for the five dimensions) plus a silly sentence. Never create a mnemonic that mixes categories (e.g. don't mix hash properties with mining rules).

**Exam trap.** The confusions examiners exploit: near-synonyms, two definitions of the same term, sign errors in calculations, "which party bears the risk".

**Exam practice.** Use real past-paper questions when available, otherwise write the questions the syllabus implies. Each answer:
1. definition → 2. named framework → 3. step-by-step application → 4. a number / example → 5. trade-offs → 6. one-line recommendation or conclusion.
Short (5-mark) answers are 120–200 words; long (10-mark) answers 250–450 words, with a table or flow where helpful.

**60-second recall.** Prompts the student can answer aloud from memory ("Recite the $100 waterfall: 1.75 / 0.25 / 0.11 / 0.50 → $97.39").
