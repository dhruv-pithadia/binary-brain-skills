# Report structure: the whole document

The reference output is `assets/examples/reference-study-guide.pdf` (FinTech, Units 1–7, 43 pages). Match its structure and tone.

## Front matter (2–3 pages)
1. **Cover** (full-bleed navy page): institution · course · code, big title ("<Course> <Exam> Study Guide"), one-sentence promise, a grid of unit titles, and a footer naming the sources (textbook + decks).
2. **How to use this guide:** 4 cards for the unit pattern (one-line idea · concepts + diagrams · cases + numbers · recall + practice), a colour legend for box types, tier tags explained.
3. **The story of the course:** one CSS flow connecting every unit with 2–4 word labels, plus a one-line caption grouping them (e.g. "Units 1–2 = lenses, 3–4 = technologies, 5–7 = business lines").
4. **Cross-cutting ideas:** the 4–6 frameworks that recur across units (the ones a student can drop into any answer).
5. **How to write a long answer:** the course's answer recipe (Define → Framework → Apply → Numbers → Trade-off → Recommendation).

## Units (one section per unit, each starts on a new page)
Follow `unit-template.md`. Typical length: 4–7 pages per unit. High-weight units get more diagrams and practice.

## End matter
1. **Night-before cheat sheet:**
   - every mnemonic, one line each, with its unit;
   - a formula board (monospace box) with every formula and worked numbers;
   - "numbers worth quoting" (two-column table);
   - a **case → concept map** (which example proves which idea).
2. **Acronym glossary:** every acronym, expanded, in one dense paragraph or table.
3. **Final readiness checklist:** 8–12 "can you…" items mapping to course outcomes.
4. **"If you blank in the exam"** fallback line.

## Optional second deliverable: Question Bank PDF
If past papers exist, build a separate PDF (see `past-papers.md`): Part A analysis → Part B answers by unit → Part C out-of-scope but frequent topics → Part D last-minute kit.

## Tone and language
- Write the way a smart senior explains things to a friend: short sentences, concrete words, no filler.
- Define every term the first time it appears. Expand every acronym on first use.
- Every framework gets an example; every example gets a number when the sources have one.
- Use the course's own vocabulary and frameworks (the lecturer's names for things), because examiners look for them.
- Mark material the user's draft lacked with **"Added from slides"** boxes, so they see what's new.
